Vue Store Adapter

Storagefy's Vue adapter provides seamless integration with Vue's reactive state management systems, particularly focusing on Pinia stores. This adapter synchronizes your Vue store state with your chosen storage backend (localStorage, sessionStorage, or IndexedDB) with minimal configuration.

1. Basic Usage

The Vue adapter works primarily with Pinia, Vue's recommended state management solution, allowing you to persist your store state across page reloads and browser sessions.

        
import { startStoragefy, getPiniaAdapter } from "storagefy";

// Initialize the storage backend
startStoragefy({
  dbName: "my-vue-app",
  adapter: "indexedDB", // or "localStorage" or "sessionStorage"
  encrypt: true,
  channelName: "vue-sync",  // the channel the tabs talk on…
  enableSyncTabs: true   // …and this storage tells them about its writes
});

// Get the Pinia adapter
const { setInStorage, getFromStorage } = getPiniaAdapter();

// Connect with your store
const userStore = useUserStore();
await getFromStorage(userStore, "user"); // Always call this before setInStorage
await setInStorage(userStore, "user", {
  timeout: 3600000, // 1 hour expiration
  ignoreKeys: ["tempData", "user.password"],
  syncTabs: true
});

2. Using the Helper Function

For a more concise approach, use the setPiniaStorage helper function:

        
import { startStoragefy, setPiniaStorage } from "storagefy";

// Initialize storage backend
startStoragefy({
  dbName: "my-vue-app",
  adapter: "localStorage"
});

// Use the helper function
const userStore = useUserStore();
await setPiniaStorage(userStore, "user", {
  timeout: 86400000, // 24 hours
  ignoreKeys: ["sessionToken", "user.password"],
  syncTabs: true
});

4. Advanced Configuration

You can directly instantiate the PiniaAdapter class for more advanced control:

        
import { PiniaAdapter, IndexedDBAdapter } from "storagefy";

// Create storage adapter instance
const storageAdapter = new IndexedDBAdapter({ 
  dbName: "my-app",
  encrypt: true
});

// Create Pinia adapter with the storage adapter
const piniaAdapter = new PiniaAdapter(storageAdapter);

// Connect with your store
const settingsStore = useSettingsStore();
await piniaAdapter.getFromStorage(settingsStore, "app-settings");
await piniaAdapter.setInStorage(settingsStore, "app-settings", {
  ignoreKeys: ["tempSettings", "user.password"],
  timeout: 604800000 // 1 week
});

5. Configuration Options

The setInStorage method accepts the following options:

Options Object

  • ignoreKeys: Array of store property keys to exclude from persistence

    Use this for sensitive data or temporary state that doesn't need persistence. Supports both flat keys and dot-notation paths for nested properties at any depth.

            
// Flat keys — exclude top-level properties
ignoreKeys: ["password", "token"]

// Nested keys — exclude properties inside objects (dot notation)
ignoreKeys: ["auth.password", "auth.token"]

// Deeply nested — works at any depth
ignoreKeys: ["config.api.secretKey", "config.api.privateToken"]

// Mixed — combine flat and nested freely
ignoreKeys: [
  "sessionToken",           // flat
  "auth.password",          // nested
  "config.api.secretKey"    // deeply nested
]

    Ignored keys are set to undefined in the persisted value. Sibling and parent keys are never affected — only the exact path specified is omitted.

  • timeout: expiration of the stored state, in milliseconds

    Counted again after each write. It is not a time limit of the operation: after it, the stored state is gone (the store keeps what it holds in memory). If not set, the state is kept until removed. A change of an ignoreKeys key alone writes nothing, so it does not renew it.

            
timeout: 3600000  // expires after 1 hour
timeout: 86400000 // expires after 24 hours
timeout: 300000   // expires after 5 minutes
  • syncTabs: Boolean flag to enable cross-tab synchronization

    When true, changes made in one browser tab will be reflected in all others in real time. Requires channelName and enableSyncTabs: true on the storage adapter — without both, nothing is synced and nothing warns you. Only a state newer than the store's is applied — every write has a revision, so an older state never undoes a newer change; two tabs changing the store at once end with the same state, the one stored (with localStorage, the tab of the newer change writes it again). With IndexedDB and localStorage, a tab shown again reads storage again.

            
// Enable tab sync
startStoragefy({
  dbName: "my-app",
  channelName: "storagefy-sync", // 1. the channel the tabs talk on
  enableSyncTabs: true            // 2. this storage tells the other tabs about its writes
});

await setInStorage(myStore, "user", {
  syncTabs: true
});
  • onError: called with an Error when the state could not be saved

    The storage is full, the encryption failed, or a change from another tab could not be read — the store keeps working. getFromStorage(store, key, { onError }) also tells a stored state that is there but cannot be read (another password, changed by hand). A mistake of the app throws instead, so it shows while developing: setInStorage rejects when its first write threw (a storage adapter of your own whose set throws, a state that cannot be copied).

            
await setInStorage(myStore, "user", {
  onError: (error) => reportToMyApp(error) // error.cause holds what failed
});

6. Handling Store Changes

The Vue adapter automatically subscribes to store changes using Pinia's $subscribe method and persists updates to your chosen storage. When data changes in other tabs (with syncTabs: true), the adapter will update the local store without triggering additional storage operations.

        
// Store changes are automatically persisted
userStore.$patch({ 
  name: "New Username",
  preferences: { theme: "dark" }
});

// The above change is automatically synchronized to storage
// and to other tabs if syncTabs is enabled

7. API Reference

getPiniaAdapter([options])

Returns a configured Pinia adapter instance. Options include:

  • adapterParams: Configuration for the underlying storage adapter

Returns: { setInStorage, getFromStorage } methods

setPiniaStorage(store, key, [options])

Helper function that internally calls getFromStorage followed by setInStorage.

  • store: Pinia store instance
  • key: Storage key string
  • options: Configuration options (ignoreKeys, timeout, syncTabs, onError)

Returns: Promise resolving to true on success

PiniaAdapter Class Methods

  • setInStorage(store, key, options): Persists store state and sets up subscription
  • getFromStorage(store, key): Loads persisted state into store — { onError } tells a stored state that cannot be read
  • destroy(key): Stops keeping the store of key — no more writes, no more changes from the other tabs. What is stored stays
  • destroyAll(): Stops keeping every store of the adapter. The storage adapter goes on
  • A Pinia state is an object: a stored value of another kind is not loaded (onError says why)

8. Best Practices

  • Always call getFromStorage before setInStorage to hydrate your store with existing data
  • Use ignoreKeys for sensitive data like authentication tokens or large temporary objects
  • Set appropriate timeout values for different types of data (e.g., longer for preferences, shorter for session data)
  • Enable syncTabs for shared state across multiple browser tabs
  • Use encryption (encrypt: true) to keep values out of plain sight — it does not protect a secret: leave tokens and passwords out of storage with ignoreKeys
